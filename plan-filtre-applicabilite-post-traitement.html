Filtre d'applicabilité (palier) — post-traitement LLM

Écarter, après extraction, les garanties qui ne valent que pour un autre palier d'offre, et le signaler à l'officier.

Projet : PolicyBot (UQAM · MCN / IAG) Date : 2026-07-21 Portée : contract/ · interview/ · report/

Contexte & objectif

La résolution de contrat (Partie A / ARP) collecte des preuves via Tavily par famille de critères (5 familles, une requête large chacune), puis extrait les faits par LLM. Un filtre d'applicabilité existe déjà (source_policy.py → source_is_allowed), mais il ne regarde que l'URL et le titre.

Conséquence : une page de garanties Enterprise / Business / API dont l'URL/titre ne porte aucun marqueur d'offre passe le filtre, et ses garanties se mélangent à celles du palier réellement évalué (ex. ChatGPT Plus). Une requête large par famille aggrave ce mélange consommateur / entreprise.

Ce plan ajoute un filtre d'applicabilité post-extraction (LLM dédié) : juger chaque preuve contre le palier courant en lisant le contenu extrait (citation + document). Une preuve qui ne vaut que pour un autre palier est rejetée et signalée à l'officier.

Invariant respecté : le filtre ne décide aucun verdict. Il n'écarte que des preuves et signale ; la Grille reste seule à trancher. Toute la partie LLM reste testable hors-ligne via FakeLLMProvider, et aucun texte n'est journalisé en clair (mask_text).
Indépendant Ce plan est autonome et livrable séparément du plan « Recherche par fait » (plan-recherche-par-fait.html) ; aucun ordre imposé entre les deux.

Mise en œuvre

1  Nouveau module policybot/contract/applicability.py

def filter_by_applicability( facts: ContractFacts, evidence: ContractEvidence, offering: ContractOfferingIdentity, llm: LLMProvider, ) -> ContractFacts: ...

Pour chaque fait dont la preuve est outcome == "accepted" :

  1. Retrouver le document source dans evidence via proof.source_url (parcours de evidence.documents_by_family) pour disposer du contenu extrait, pas seulement de l'URL/titre.
  2. Construire le prompt : palier courant (offering.display_label(), plan, deployment_mode, contract_type), nom du fait, citation verbatim (proof.quote) et une fenêtre de contexte autour de la citation dans document.content (réutiliser arp.py::_select_evidence_text).
  3. Appel LLM structuré → applies_to_offering: "yes" | "no" | "unclear", offer_mentioned, reason ; run_name="filter_applicability:<champ>", task="contract_applicability".
  4. Décision :
    • no rejet : preuve recopiée avec value="unknown", outcome="applicability_rejected", note explicite ; champ de ContractFacts remis à "unknown".
    • unclear conservé + signalé : preuve inchangée, fait marqué pour confirmation officier.
    • yes inchangé.
  5. Robustesse & audit : journalisation via mask_text (jamais de texte en clair) ; une erreur LLM dégrade ce seul fait (conservé + signalé), jamais l'entrevue. Idempotent : on ne traite que les preuves accepted.

2  Modèles policybot/models.py

  • EvidenceOutcome (l.17-25) : ajouter le membre "applicability_rejected".
  • RiskFactor (l.244-253) : ajouter needs_officer_confirmation: bool = False — matérialise le « drapeau officier » côté Partie A (aligné avec Usage.needs_officer_confirmation).

3  Câblage policybot/interview/orchestrator.py

Insérer l'appel entre l'extraction et build_arp (l.108-109), là où evidence, offering et self._llm sont déjà en portée :

facts = extract_contract_facts(evidence, self._llm) if offering is not None: facts = filter_by_applicability(facts, evidence, offering, self._llm) # nouveau ... arp = build_arp(tool_name, iag_type, facts, offering)

Optionnellement désactivable via POLICYBOT_CONTRACT_APPLICABILITY=off (défaut activé).

4  Propagation du drapeau (arp.py::build_arp)

Quand la preuve d'un champ porte outcome == "applicability_rejected" (ou fait unclear), positionner needs_officer_confirmation=True sur le RiskFactor correspondant. _observation (arp.py:386-403) affiche déjà proof.note → l'officier lit la raison sans changement de format.

5  Rendu rapport

Surfacer RiskFactor.needs_officer_confirmation dans report/renderer.py + report/templates/report.html.j2 (et web/templates/resultat.html.j2 si la Partie A y figure) : un marqueur « à confirmer par l'officier » sur la ligne concernée.

Risques & points d'attention

Coût LLM. Le filtre ajoute un appel LLM par preuve acceptée (≤ ~19). Acceptable ; désactivable via env. Possibilité de ne filtrer que les faits « importants ».
Faux rejets. Un no erroné efface une preuve valide. Mitigation : unclear conservé + signalé plutôt que rejeté ; drapeau officier partout ; reason/offer_mentioned visibles dans le rapport.
Portée du contenu. Réutiliser le fenêtrage _select_evidence_text pour ne pas envoyer tout le document au LLM (coût + bruit).
