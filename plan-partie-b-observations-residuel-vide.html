Partie B — Observations explicatives + risque résiduel vide

Expliquer chaque cote inhérente de la Partie B par les règles YAML déclenchées, et vider la colonne « Risque résiduel » dans tout le rapport.

Projet : PolicyBot (UQAM) Date : 2026-07-21 Portée : Partie A + Partie B du rapport

Objectif

Deux changements ciblés sur la grille d'évaluation des risques :

  1. Partie B — observations explicatives : aujourd'hui la colonne « Observations » de la Partie B (grille des usages) est vide. On veut qu'elle explique pourquoi chaque critère reçoit sa cote inhérente (F/M/E/C), en s'appuyant sur le texte des règles grille.yaml déclenchées.
  2. Risque résiduel vide partout : la colonne « Risque résiduel » doit être vide dans tout le document (Partie A et Partie B). C'est un champ que l'officier de sécurité/vie privée remplit lui-même lors de sa révision — PolicyBot ne le pré-remplit plus.
Invariant respecté. Ces changements sont purement descriptifs (texte + affichage). Ils ne touchent ni la matrice MCN, ni le verdict, ni les cotes calculées. Le moteur grille reste le seul décideur ; on ne fait qu'expliquer et présenter.

Plan d'implémentation

Approche TDD : ajuster/ajouter les tests d'abord (rouge), puis le code (vert). Chaque phase reste indépendamment testable.

Phase 1 — Modèle : rendre le résiduel optionnel

  1. models.py : passer residual: RiskLetter → residual: Optional[RiskLetter] = None dans RiskFactor. Optional est déjà importé.
  2. Vérifier qu'aucune validation Pydantic ailleurs n'exige un résiduel non nul (recherche .residual dans tout le paquet).

Phase 2 — Partie B : observations + résiduel vide

  1. engine.py _build_partie_b() : en plus des lettres, collecter par critère la liste des conditions des règles déclenchées (rule.then.get("conditions", [])).
  2. Construire l'observation selon le critère :
    • « Fuite de données confidentielles » → « Coté <Niveau> car les données sont classées <Classification>. »
    • Critère avec ≥1 règle déclenchée → « Coté <Niveau> car <condition 1> | <condition 2> … (<R-xx, R-yy>) » — les identifiants des règles sources sont ajoutés en discret entre parenthèses à la toute fin.
    • Critère sans règle (F par défaut) → « Aucune règle de la grille déclenchée — risque inhérent de base (Faible). »
  3. Ajouter un mappage lettre → mot de niveau ({"F":"Faible","M":"Modéré","E":"Élevé","C":"Critique"}) pour composer « Coté <Niveau> ».
  4. Mettre residual=None sur chaque ligne de la Partie B (au lieu de residual=letter).
Point d'attention — règles « Rappel » (R-28 → R-32). Ces règles se déclenchent toujours (when: {}) mais n'ont pas de risk_level ; le code actuel leur attribue par défaut la lettre M (engine.py:28, … if level else "M"). L'observation exposera donc « Coté Modéré car Rappel : … », ce qui peut surprendre. À trancher en Phase 2 — voir Questions ouvertes.

Phase 3 — Partie A : résiduel vide

  1. arp.py : remplacer chaque residual=<risque> par residual=None sur les ~14 RiskFactor (lignes 136–264). Les observations existantes restent inchangées.

Phase 4 — Rendu (vérification uniquement)

  1. Confirmer que report.html.j2 affiche bien une cellule vide pour residual=None (déjà géré par or ""). Aucune modification attendue, sauf si un autre gabarit/route affiche le résiduel sans garde.
  2. Vérifier le rendu DOCX/PDF (renderer.py : write_docx/write_pdf) — s'assurer qu'un résiduel None n'y provoque pas d'erreur (chaîne vide attendue).

Phase 5 — Tests

  1. tests/contract/test_arp.py & tests/helpers/arp_fixtures.py : mettre à jour les attentes de résiduel (désormais None) ; les observations restent vérifiées.
  2. Tests moteur grille (Partie B) : ajouter des assertions sur le contenu des observations (les 3 formes) et sur residual is None.
  3. tests/report/test_renderer.py : vérifier que la colonne « Risque résiduel » rend une cellule vide et que les observations Partie B apparaissent.
  4. tests/test_golden_scenarios.py : ajuster le scénario UQAM de référence si des cotes résiduelles y étaient attendues.

Phase 6 — Vérification finale

  1. Lancer pytest -v (suite complète, hors-ligne et déterministe) — seul gate du projet.
  2. Générer un rapport de bout en bout et inspecter visuellement Partie A + Partie B (résiduel vide, observations présentes).
