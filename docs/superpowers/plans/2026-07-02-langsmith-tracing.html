LangSmith Tracing Layer for PolicyBot

Give every LLM-assisted step (classification, extraction, drafting) visible, inspectable traces in LangSmith for solo dev debugging — without changing the deterministic decision engine or the LLMProvider interface.

Date: 2026-07-02 Scope: LLM call instrumentation only Audience: solo dev Priority: after core pipeline lands

Overview & Goal

PolicyBot's LLM calls (policybot/llm/openrouter.py) currently go straight to OpenRouter over raw httpx. That's outside LangChain, so nothing shows up in LangSmith automatically. The fix is to swap the OpenRouter client for LangChain's ChatOpenAI (pointed at OpenRouter's OpenAI-compatible endpoint) — this gets LangSmith tracing essentially for free, and will also cover the planned LangGraph interview orchestrator once it's built, since LangGraph nodes trace natively through the same env vars.

Decided scope (from requirements pass): dev-debugging traces only, not a compliance audit trail. Solo-dev LangSmith account. Trace all LLM-assisted call sites, not just the tricky ones. Execute this after the current 16-task implementation plan's core pipeline (interview → grille → PDF) is functional — this document is written now so it's ready to pick up then.

Phase 0 — LangSmith account & project (manual, ~5 min)

  1. Step 1: You already have a LangSmith account/API key — just create a new project for this app. Suggested name: policybot (or policybot-dev to keep it separate from any future prod project).
  2. Step 2: Copy the API key from LangSmith settings (Settings → API Keys). Do not commit it — it goes in a local .env file (gitignored), same pattern as the eventual OPENROUTER_API_KEY.

Phase 1 — Dependencies & environment config

  1. Step 1: Add langchain-openai and langsmith to pyproject.toml dependencies (alongside the existing langgraph>=0.2, which already pulls in langsmith as a transitive dep — pin it explicitly anyway for clarity).
  2. Step 2: Add a .env.example (if one doesn't exist) documenting the required variables, and confirm .env is in .gitignore.
  3. Step 3: Load env vars at process startup (wherever the app entrypoint / FastAPI startup lives) via python-dotenv or equivalent, consistent with however OPENROUTER_API_KEY ends up being loaded.

Keep tests clean. Do not set LANGCHAIN_TRACING_V2 in the test environment (pytest config / CI). Tests use policybot/llm/fake.py, which never calls out to a real model anyway, so this mostly matters if a test ever exercises OpenRouterProvider directly against a live key.

Phase 2 — Migrate OpenRouterProvider to langchain-openai

Keep the existing LLMProvider ABC (complete_json, draft_text) completely unchanged so every current and future call site is unaffected. Only the internals of policybot/llm/openrouter.py change.

  1. Step 1: Replace the httpx.Client with langchain_openai.ChatOpenAI, setting base_url="https://openrouter.ai/api/v1" and api_key from the constructor arg (OpenRouter is OpenAI-compatible, so this is a drop-in swap).
  2. Step 2: complete_json → call ChatOpenAI with model_kwargs={"response_format": {"type": "json_object"}}, matching the current JSON-mode behavior, then json.loads(response.content).
  3. Step 3: draft_text → plain invocation, return response.content.
  4. Step 4: Tag each call site with a run_name / tags (see Phase 4) so traces are distinguishable in the LangSmith UI without opening each one.
  5. Step 5: Verify existing behavior/error handling (e.g. HTTP errors, timeouts) is preserved or intentionally improved — ChatOpenAI's error surface differs slightly from raw httpx.raise_for_status().
Why this approach over manual @traceable: since the planned LangGraph interview orchestrator will already be part of the stack, standardizing all LLM calls on LangChain means tracing is consistent end-to-end with zero extra decorators once that orchestrator exists — one instrumentation strategy for the whole app, not two.

Phase 4 — Per-call metadata & tags

Raw traces are only useful if you can tell them apart at a glance. Pass tags and a run_name (or LangSmith metadata) per call site:

provider.complete_json( system=..., user=..., tags=["data_classification"], run_name="classify_data_sensitivity", )
  • Suggested tags: data_classification, tool_type_classification, arp_extraction, grille_proposal, report_drafting.
  • If complete_json/draft_text need new optional kwargs to carry tags through to ChatOpenAI.invoke(..., config={...}), add them with defaults so existing call sites don't break.

Phase 5 — Tests stay isolated

  1. Step 1: policybot/llm/fake.py (used across the test suite) needs no changes — it never touches ChatOpenAI or the network.
  2. Step 2: If any test exercises OpenRouterProvider directly, make sure it either mocks ChatOpenAI or is skipped without a real API key/tracing enabled.
  3. Step 3: Run the full suite (pytest) after the migration to confirm nothing regresses.

Risks & Mitigations

Risk — JSON mode compatibility. OpenRouter's response_format: json_object support varies by underlying model. Verify it still works identically through ChatOpenAI.model_kwargs for the Gemma model in use before trusting complete_json in production paths.
Risk — API key hygiene. Two secrets now (OPENROUTER_API_KEY, LANGCHAIN_API_KEY). Keep both in .env only, never in code or committed config.
Non-risk — sensitive data exposure. Per PolicyBot's existing design, interview entries sent to the LLM are already metadata/descriptions only, never the sensitive data itself — so LangSmith traces won't contain anything more sensitive than what already goes to OpenRouter today.

Success Criteria

  • Every LLM-assisted call site listed in Phase 3 produces a visible, correctly-tagged trace in the policybot LangSmith project.
  • LLMProvider's public interface (complete_json, draft_text) is unchanged for all existing callers.
  • Tracing is togglable via LANGCHAIN_TRACING_V2 with no code changes.
  • No secrets committed; full test suite passes with tracing disabled.
