The 70-test floor, and why it isn't arbitrary

The suite currently collects 126 tests. 65 of them live in tests/web/ and tests/api/ and disappear with the wizard. That leaves 61, plus the new ingestion tests.

126 collected today −65 tests/web + tests/api (deleted with the wizard) = 61 surviving +12 tests/intake (minimum required) = 73 → floor of 70 leaves a little slack, and still blocks quietly dropping a dozen real tests
A floor of 100 — the intuitive round number — would have made this goal mathematically impossible and burned all 40 turns against a wall. The number was measured, not guessed.

Failure modes

False yes — the plausible stub. A CLI that prints 35 lines from a hardcoded list satisfies check 3 without a schema behind it. Checks 2 and 4 are the guard: 12 real tests and a dry-run that resolves an actual offering identity from an actual .xlsx. Worth eyeballing configs/formulaire.yaml and intake/schema.py yourself when the loop ends.
Irreversible — questions deleted before transcription. If Phase 4 runs before Phase 0, the 35 questions are gone from the working tree. They stay in git history, but the loop would not notice the loss and would happily rebuild a thinner form. This is why Phase 0 and its separate commit are written into the condition itself, not left to the plan.
Runaway — the unfixable check. If git grep keeps matching a symbol in a file nobody thought to touch, the loop grinds. The 40-turn bound catches it; /goal shows the evaluator's latest reason if you want to see where it is stuck.
Out of reach of the loop. Nothing here proves a real Microsoft Forms export parses — the fixture is written by the same code that reads it. Send yourself the form, export it, and run --dry-run on the genuine file. That step is yours.

Before you start

  • Requires Claude Code v2.1.139+.
  • The workspace must be trusted — the evaluator runs through the hooks system.
  • Unavailable if disableAllHooks or allowManagedHooksOnly is set.
  • A goal does not change permissions. In default mode Claude still asks before each unallowed tool call. You chose to run this unattended — turn on auto mode first, or you will be answering prompts for 40 turns.
  • Commit or stash your work first. This goal deletes about twenty files.
Only one goal per session; setting a new one replaces the old. /clear also drops it.

Operating the loop

/goal # status: condition, turns, elapsed, tokens, latest reason /goal clear # stop before the condition is met (aliases: stop, off, reset, none, cancel)
On --resume/--continue, the condition carries over but the turn count, timer and token baseline reset. Achieved or cleared goals are not restored.
Headless: claude -p "/goal <condition>" prints nothing until the condition is met — add --output-format stream-json --verbose to watch the loop. Ctrl+C stops it.
