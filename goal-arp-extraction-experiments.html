  • configs/prompts.yaml — the centralized prompt catalogue, loaded and validated by policybot/prompts.py. The prompts.contract_extraction entry holds the system message and the user_template (variables $fields and $evidence, rendered with string.Template). This is the primary lever, and the only place prompt wording may change.
  • policybot/contract/arp.py — _quote_is_anchored() / _accept(): a value with no anchored verbatim quote collapses to unknown. This guardrail is the main source of the 30 abstentions. Note it works with the prompt: the system message already ends with "If you cannot quote the evidence, answer unknown", so the model and the code are both pushing toward abstention.
  • policybot/contract/families.py — the 5 criteria families (one Tavily search each) and ALL_FACT_FIELDS with their allowed_values.
  • runs/arp/2026-07-16/snapshots/*.json — the frozen raw Tavily calls replayed by SnapshotTavilyClient. Changing a query invalidates them: a snapshot mismatch raises "Snapshot Tavily incompatible", which is the signal that this iteration needs --source live.

Failure modes

The abstention/wrong-value seesaw. Loosening the quote-anchoring guardrail converts WRONG_ABSTAIN into MATCH and into WRONG_VALUE at the same time. Since the condition rewards logged iterations rather than a score, the loop won't chase MATCH blindly — but the RESULTS.md ranking must sort on WRONG_VALUE ascending as a tiebreak, or a reckless variant wins. For PolicyBot a wrong contract fact is worse than an admitted gap: it feeds the grille as if it were established.
Live-run drift. An iteration on --source live re-records the snapshots, so every later snapshot run scores against different evidence and is no longer comparable to iterations 6–9. Any iteration that goes live should say so explicitly in its report and re-baseline; otherwise the delta table is measuring Tavily's mood, not your change.
configs/ is untracked — git will not save you. git status reports the whole directory as a single ?? configs/, so there is no committed baseline for configs/prompts.yaml or configs/policybot.yaml and git checkout cannot undo a prompt edit. Iteration 12's prompt would silently overwrite iteration 8's with no way back. That's why every iteration archives its two config files under runs/arp/2026-07-16/configs/iteration-N/: the archive is the version history for the duration of the experiment.
UTF-16 run files. The existing iteration-*.txt were written with PowerShell's >, which encodes UTF-16 — that's why they read as spaced-out characters and mojibake (Résumé → R��s�um��) in most tools. Redirect with | Out-File -Encoding utf8 so the new runs stay greppable and diffable.

Before you start

  • Requires Claude Code v2.1.139+.
  • The workspace must be trusted — the evaluator runs through the hooks system.
  • Unavailable if disableAllHooks or allowManagedHooksOnly is set.
  • A goal does not change permissions. In default mode Claude still asks before each unallowed tool call. Pair with auto mode to run unattended — 40 turns of manual approvals is not a loop, it's a chore.
  • OPENROUTER_API_KEY must be in .env — the harness calls the real provider even on snapshot runs (only Tavily is replayed, never the LLM). Each iteration therefore costs 3 extraction calls × 5 families.
  • TAVILY_API_KEY is needed only for the --source live iterations.
Only one goal per session; setting a new one replaces the old. /clear also drops it.

Operating the loop

/goal # status: condition, turns, elapsed, tokens, latest reason /goal clear # stop before the condition is met (aliases: stop, off, reset, none, cancel)
On --resume/--continue, the condition carries over but the turn count, timer, and token baseline reset. Achieved or cleared goals are not restored.
Headless: claude -p "/goal <condition>" prints nothing until the condition is met — add --output-format stream-json --verbose to watch the loop. Ctrl+C stops it.

Why /goal and not /loop

ApproachNext turn starts whenStops when
/goalThe previous turn finishesA model confirms the condition is met
/loopA time interval elapsesYou stop it, or Claude decides the work is done
Stop hookThe previous turn finishesYour own script or prompt decides
/goal fits here: an iteration takes as long as it takes (an edit, an eval run, a report), so a wall-clock interval would cut runs in half or idle between them. The work is also session-scoped and one-off — a Stop hook would apply to every future session in this repo, which is not what you want for an experiment.
